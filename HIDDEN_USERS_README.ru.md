# Функция скрытия пользователей (Hidden Users)

*[English version](HIDDEN_USERS_README.en.md)*

## Описание
Реализована функция скрытия пользователей из списков визуализации в Telegram Desktop на основе списка user ID.

## Как это работает

### 1. Чтение списка userid из файла
- Файл: `hidden_users.txt`
- Расположение: 
  - В первую очередь ищется в текущей директории запуска приложения
  - Если не найден, используется директория данных приложения (AppDataLocation)
- Формат: один user ID на строку (числовой формат)
- Комментарии: строки, начинающиеся с `#` или `//`, игнорируются

### 2. Исключение из визуализации
Скрытые пользователи исключаются из следующих списков:
- Списки участников групп и каналов (`edit_participants_box.cpp`)
- Списки чатов (`peer_list_controllers.cpp` - ChatsListBoxController)
- Списки контактов (`peer_list_controllers.cpp` - ContactsBoxController)
- Сообщения скрытых пользователей **в группах** (`history_view_list_widget.cpp` - `ListWidget::refreshRows`)
- Сообщения скрытых пользователей в глобальном и внутричатовом поиске сообщений, если найденное сообщение не из личного чата с самим этим пользователем (`dialogs_inner_widget.cpp` - `InnerWidget::searchReceived`)

**Важное исключение:** если открыт личный чат (1-на-1) с самим скрытым пользователем, его сообщения там **отображаются как обычно** — раз уже открыли переписку с ним намеренно, прятать содержимое бессмысленно. Скрытие сообщений работает только там, где скрытый пользователь пишет среди других (группы). Это же исключение применяется к поиску сообщений и к desktop-уведомлениям — сравнивается `item->from()` (отправитель) с `history()->peer` (пир открытого треда).

### 3. Поиск через @username
- При поиске по @username (поиск пиров/контактов) скрытые пользователи **находятся**
- Это позволяет открыть чат со скрытым пользователем при необходимости
- Фильтрация peer-поиска происходит только в методах `appendRow()` и `prependRow()`, но не в `createSearchRow()`
- Поиск **сообщений** (Ctrl+F, глобальный поиск) при этом фильтрует сообщения от скрытых пользователей — они не отображаются в результатах

### 4. Упоминания (@mention) в тексте сообщений
- `@username`-упоминание скрытого пользователя маскируется прямо в тексте: символы юзернейма заменяются на `•` (длина сохраняется, чтобы не сдвигать офсеты остальных entities), плюс убирается ссылка/подсветка
  - Маскировка нужна, иначе сам юзернейм остаётся читаемым текстом, и его можно вручную вбить в поиск, чтобы найти скрытого пользователя
- Текстовые упоминания без юзернейма (`MentionName`, кликабельное имя без `@`) скрытого пользователя лишаются только ссылки/подсветки — сам текст имени не маскируется, так как он не содержит поискового юзернейма
- Реализовано в `HistoryItem::translatedTextWithLocalEntities()` (`history_item.cpp`): `@username` резолвится в пира через `peerByUsername()`, `MentionName` — напрямую по `userId`, зашитому в entity

### 5. Уведомления
- Сообщения от скрытых пользователей не показывают desktop-уведомление (имя + текст), **кроме** сообщений из личного чата с самим этим пользователем — проверка стоит в `Window::Notifications::System::schedule()` (`notifications_manager.cpp`), рядом с уже существующей проверкой `isMessageHidden()`

### 6. Логирование
Все действия логируются в консоль с префиксом `[HiddenUsers]`:
- Загрузка файла со списком ID
- Количество загруженных ID
- Пропущенные некорректные строки
- Каждый случай пропуска скрытого пользователя в списке

## Пример файла hidden_users.txt

```
# Список скрытых пользователей
# Один ID на строку

# Примеры:
123456789
987654321
# Это комментарий
// Это тоже комментарий
```

## Технические детали

### Изменённые файлы:
1. `Telegram/SourceFiles/hidden_users_manager.h` - заголовочный файл менеджера
2. `Telegram/SourceFiles/hidden_users_manager.cpp` - реализация менеджера
3. `Telegram/SourceFiles/boxes/peers/edit_participants_box.cpp` - скрытие в списках участников
4. `Telegram/SourceFiles/boxes/peer_list_controllers.cpp` - скрытие в списках чатов и контактов
5. `Telegram/SourceFiles/history/view/history_view_list_widget.cpp` - скрытие сообщений в открытом чате (`ListWidget::refreshRows`)
6. `Telegram/SourceFiles/dialogs/dialogs_inner_widget.cpp` - скрытие сообщений в результатах поиска (`InnerWidget::searchReceived`)
7. `Telegram/SourceFiles/history/history_item.cpp` - снятие ссылки с упоминаний скрытых пользователей (`translatedTextWithLocalEntities`)
8. `Telegram/SourceFiles/window/notifications_manager.cpp` - подавление desktop-уведомлений (`System::schedule`)
9. `Telegram/CMakeLists.txt` - добавлены файлы менеджера в сборку

### Инициализация
Загрузка списка скрытых пользователей происходит автоматически при создании сессии в `main_session.cpp` (строка 308):
```cpp
HiddenUsersManager::Instance().loadFromFile();
```

### API для проверки
```cpp
if (HiddenUsersManager::Instance().isHidden(peerId)) {
    // Пользователь скрыт
}
```

## Примечания
- Скрытие работает только для пользователей (PeerIdType::User)
- Группы, каналы и другие типы пиров не скрываются
- User ID должны быть в числовом формате (bare ID без префиксов)
- Файл `hidden_users.txt` отслеживается через `QFileSystemWatcher` — изменения подхватываются на лету (`HiddenUsersManager::watchFile`), список ID перечитывается заново (включая удаление ID из файла); уже открытые списки/чаты обновятся при следующем их естественном пересчёте, принудительного мгновенного перерисовывания нет
- Всё скрытие — только на уровне отображения (UI): сами данные сообщений, счётчики непрочитанного и история загружаются как обычно, ничего не удаляется и не блокируется на уровне сети/данных
